---
name: SEO metadata pipeline
description: Where tara-ev page titles/meta descriptions come from and what to keep in sync
---
Titles and meta descriptions for all routes are curated in `artifacts/tara-ev/public/content/routes.json`. Three consumers must stay in sync: client-side (`src/App.tsx`), build prerenderer (`scripts/prerender.mjs`), and dev middleware (`vite.config.ts`). Prerender + dev middleware prefer `routeMeta.description` with HTML extraction as fallback only.

**Why:** a review rejected an edit that changed routes.json only — static HTML crawlers receive kept old extracted, ellipsis-truncated descriptions.

**How to apply:** the build (`pnpm run build` with PORT set) runs `assertSeoMeta` on all generated pages: exact title/description match to routes.json, nonempty, ≤160 chars, no trailing ellipsis. Description conventions: unique branded title with TARA, explicit US framing, no overseas/global/export terms, never the banned old brand phrases (verify-removals.sh greps routes.json too). Dev middleware only rewrites requests with `Accept: text/html` — curl needs that header when testing.

**SEO/AI file suite:** the extended XML suite (category sitemaps, RSS/Atom feeds, product feeds, hreflang/mobile/geo sitemaps, sitemap.xml index) is generated by `artifacts/tara-ev/scripts/generate-seo-files.mjs` from routes.json — rerun it after route changes instead of hand-editing those XML files. robots.txt lists all sitemap URLs.

**Never run prerender.mjs twice:** `pnpm run build` already runs the prerenderer internally with the clean Vite shell. Running `node scripts/prerender.mjs` again afterwards uses the already-prerendered `dist/public/index.html` (home content baked in) as the shell and silently stamps homepage content into all 544 pages. One build = done.

**Copy rules enforced at build:** assertSeoMeta in prerender.mjs now also requires every curated description to contain "TARA Dealership"/"TARA Golf Cart Dealership", explicit US framing (US/American/nationwide), and no overseas/global/legacy-brand terms — copy edits violating these fail `pnpm run build`.

**Social share images:** every route must have a curated local `ogImage` in routes.json. Blog/news mappings are derived from article bodies because whole-page extraction grabs shared navigation thumbnails. Keep Open Graph and Twitter images identical in both build prerendering and dev middleware.
